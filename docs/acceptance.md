# Product candidate acceptance

This walkthrough covers the initial product and the completed [everyday table workflows and UI refinements](refinement-plan.md). The [current candidate report](ui-refinement-validation.md) identifies the exact package, automated checks, historical measurement references and pending manual checks. The owner still decides whether the complete workflow meets their needs. This is a private evaluation build, not a formal public release.

## Candidate and verification

The Windows ZIP, checksum and exact source revision are identified by `release/latest.json`. Extract the whole ZIP and start `rowweave.exe`; the desktop includes its runtime. Use a fresh workspace for acceptance. To isolate it from an existing profile, set `ROWWEAVE_DATA_DIR` to a new directory before launch. The default database filename `prototype.sqlite` is retained for compatibility; fresh workspaces contain no sample records.

Source/service setup is in [development.md](development.md) and [service.md](service.md). The SDK, CLI, MCP and Harness archives are built with the corresponding `package:*` scripts; [agent Skills](agent-skills.md) are installed from the repository. No npm publication or AI account is required for RowWeave itself.

The [current candidate report](ui-refinement-validation.md) records the clean source revision, ZIP checksum, all 150 Node tests on both CI platforms, passing feature CI, and final extracted-package/shared-interface checks. The local IPv6 fixture runs in CI because this environment cannot bind it. Historical performance/native reports retain their original artifact identifiers; this UI-only iteration does not claim a new performance benchmark.

## Owner walkthrough

1. **Model your own work.** Create `Projects` and `Tasks`. Give Projects a currency-formatted Budget, a date, and a single-select Status with your own options. Add a checkbox and multiline Notes to Tasks. Rename/reorder fields and change an option label; existing data must remain intact. In Manage fields, choose another primary display field; duplicate display values are allowed. Open Record identity and Field identity to distinguish the record's primary-key UUID from a column's UUID.
2. **Edit and persist.** Create, duplicate and delete records. Use Enter, Tab, arrows, selection, Undo/Redo and Ctrl+S. Enter Chinese through your normal IME, including canceling a composition. Close and reopen the app; saved schema, records and views must remain.
3. **Check an unsafe conversion.** Add a text Code field with `10` and `not a number`. Preview a conversion to Number: the invalid record must be identified and application must leave stored data unchanged. Correct it to `20`, then preview/apply successfully.
4. **Keep useful views.** Save a view with more than one filter and sort key. Use a column menu to configure, sort, hide or move it; also try right-click and Shift+F10. In Display, change row density and freeze the leading column; scroll horizontally and verify that it stays visible. Reopen the view and verify its layout. Edit a sorted record and confirm that the intended record changes. Make a conflicting update through a second client; the first client's unsaved draft must remain available for deliberate resolution.
5. **Connect records.** Add a Tasks → Projects relation and a lookup of Project Budget. Select a project by its name and open its details. Rename the project and update its budget; refresh Tasks and verify the label and lookup. Try deleting a referenced record/field and check the stated dependency policy.
6. **Exchange real data.** Copy/paste a rectangle from your spreadsheet, including Chinese, emoji, quoted text, blank cells and multiline text. Copy it back and compare. Import a mapped UTF-8 CSV, export the current view, and reimport supported values. Try an invalid typed value: the batch must fail without partial stored changes. Use an isolated pressure workspace for the optional 1,000 × 10 paste check.
7. **Connect an agent or application.** Follow the [MCP](mcp.md), [CLI](../apps/cli/README.md), [SDK](../packages/client/README.md), or [Harness](harness.md) guide. Point it at the same service as the desktop. Discover schema, add a record, query a saved view, then verify the change in the other interface. Use current versions for writes.
8. **Recover deliberately.** With an isolated remote service, stop it during editing and confirm the draft/error behavior. Restart it and inspect stored data before repeating a write with an uncertain outcome. Create an online backup, restore it to a new path, and connect to the restored workspace using the [backup guide](backup.md).
9. **Track status on a board.** Add a single-select Status to Tasks and create a Board view grouped by it. Open a card, create a record in an empty column, and move a card using both drag and its Move selector. Filter/search the board, then return to a grid. Counts must reflect all matching records, including unloaded cards.
10. **Calculate a field.** Add Quantity and Price numbers, then a Formula named Total with `["Quantity"] * ["Price"]`. Choose currency formatting. Save source changes and confirm the result, rename Quantity and reopen the formula, then test `1 / 0`: the field must show an explicit error. Results cannot be directly edited or pasted over. See the [formula guide](formulas.md) for the bounded language.
11. **Summarize linked numbers.** On Projects, link multiple Tasks and add a Lookup of Task Total with Sum selected. Confirm that changing a task's saved input changes the project's next read. Try Count numeric values, an empty link list, zero and null inputs. Check the [linked-summary semantics](linked-summaries.md).
12. **Review the whole view.** Open Summarize, choose a numeric field (including a formula or linked summary), and group by Status. Check sum/average/min/max against a small known dataset. Apply a saved filter and search; record counts and measures must follow both. Results should cover all matching rows rather than only the visible page.
13. **Check the workspace layout.** Switch view tabs with arrows/Home/End and Enter, including enough views to scroll horizontally. Open Filters and Sort separately, save one, and verify the other rules and temporary search remain. Open a record from both a grid and a board; try many fields, explicit Save/Cancel, and closing an unsaved draft with Escape. Configure a field from its column menu, scroll a long option list, and preview a conversion. Repeat at a narrow window size and confirm that the table context, relevant controls and keyboard focus remain usable.
14. **Use calendar-relative dates.** Filter a date or timestamp with Today, This week or Past N days and choose an explicit time zone. Past/next day counts include today. Reopen the filter and check its settings, compare the records with Summarize and a fresh CSV export, then refresh after the calendar period changes. Test an invalid zone and a concurrent view edit; the filter draft must remain available for correction. See the [relative-date guide](relative-date-filters.md).

Record the candidate checksum, OS/display refresh rate/input method/spreadsheet versions, the failing step if any, expected versus observed behavior, and a screenshot or minimal sample without private data. Include scrolling on your normal display: the earlier full reference run used 60 Hz, while the final-binary rerun encountered a 32 Hz desktop session and cannot establish a 60 Hz frame-interval result. The product is ready for owner acceptance only after the required implementation and verification items in the completion plan are complete; this document does not accept it on the owner's behalf.

## Current boundaries

- Windows x64 portable desktop; one workspace per service. The bearer token grants full workspace access. This is not enterprise authorization or live collaborative editing.
- Explicit saves, version conflicts and refreshes; no offline replication or automatic retry of writes.
- Custom typed schema, bounded scalar formulas including linked-summary inputs, two-way links, one-hop lookups/numeric summaries, grids with one single-select/checkbox grouping level, and single-select board views. Acyclic formula/summary chains are supported; recursive calculations and direct lookup-to-lookup targets are not. No arbitrary JavaScript formulas, attachments, dashboards, further view families or built-in AI runtime.
- Saved scalar filter/sort indexes cover the documented performance workloads. Relation/lookup/array searches remain supported scan paths; arbitrary queries are not covered by those timing claims.
- Spreadsheet formats and input methods vary. Use the CSV guide's empty-value, date/time and formula-like-text semantics, and include your normal applications in final manual acceptance.
