# Product candidate acceptance

This walkthrough covers the implemented scope in [Workflow gap closure](gap-closure-plan.md). The [candidate validation report](final-candidate-validation.md) identifies the exact package, completed checks, performance measurements and any remaining verification. The owner decides whether the complete workflow meets their needs. This is a private evaluation build, not a public release.

## Start with an isolated workspace

The Windows ZIP, checksum and source revision are recorded in `release/latest.json`. Extract the whole ZIP and start `rowweave.exe`; the desktop includes its runtime. Set `ROWWEAVE_DATA_DIR` to a new directory before launching if another profile already contains working data. Fresh workspaces contain no sample records. The default database filename `prototype.sqlite` is retained for compatibility.

Source setup is in [development](development.md); deployment and authentication are in [service operations](service.md). The SDK, CLI, MCP and Harness archives have corresponding `package:*` scripts. [Agent Skills](agent-skills.md) are installed from the repository. RowWeave requires neither an npm publication nor an AI account.

Run `npm test`, `npm run test:desktop` and `npm run test:harness` for source checks. After `npm run package:win`, run `npm run test:packaged` and `npm run test:interfaces`. Windows and Linux CI cover the configured regressions. Reference-machine performance and native interaction have their own evidence in the candidate report; synthetic composition or DOM clipboard events do not establish native compatibility.

## Owner walkthrough

1. **Model your work.** Create Projects and Tasks. Add a currency Budget, dates, a colored Status choice, a checkbox and multiline Notes. Add field descriptions and defaults. Rename/reorder fields and option labels; existing values and IDs must remain intact. Choose another primary display field in Manage fields. Duplicate or empty display values are allowed unless separately constrained. Record identity shows the record's immutable primary-key UUID; Field identity shows the column's separate UUID.
2. **Edit and persist.** Create and duplicate records. Use Enter, Tab, arrows, rectangular selection, draft Undo/Redo and Ctrl+S. Enter Chinese with your normal IME, including confirming and canceling composition. Restart; saved schema, data and views must remain.
3. **Preview a conversion.** Create a text Code field containing `10` and `not a number`. Preview Number conversion: the invalid record must be identified and applying must leave all stored data unchanged. Correct it to `20`, then preview/apply. A concurrent schema change must be reported instead of overwritten.
4. **Arrange focused views.** Save multiple filter and sort rules. Use column menus, right-click or Shift+F10 to configure, hide, move and sort fields. Change density and frozen columns. Reopen the view and verify layout. Edits after sorting must still address the intended record UUID.
5. **Keep drafts during external changes.** Update saved data from a second client. Idle views should refresh. Keep a grid or record draft open during another update: typed text, composition, selection and focus must remain usable. A stale save must report a conflict and retain the draft for deliberate resolution. Try a failed read and reconnect without blindly repeating a write.
6. **Connect records from either side.** Link Tasks to Projects and create the inverse field. Edit links from both tables and check matching values. Pair two compatible existing one-way fields without losing links. A conflicting single-link choice must fail atomically. Removing one paired field retains the other as one-way links. See [pairing](relation-pairing.md).
7. **Follow linked values and totals.** Look up Project Budget from Tasks. Add a third table linked to Tasks and configure a lookup of that existing lookup; test array and numeric summary choices. Change a leaf value and check the next result, formatting, nulls and errors. Try a cycle: saving must fail with an explanation and retain the draft. See [chained lookups](chained-lookups.md).
8. **Exchange real spreadsheet data.** Copy a rectangle containing Chinese, emoji, quotes, commas, blanks and multiline text from your spreadsheet. Paste, save, copy back and compare. Import mapped UTF-8 CSV and export/reimport supported values. One invalid typed value must reject the batch without partial stored changes. Use a pressure-test workspace for a 1,000 × 10 paste. See [data exchange](data-exchange.md).
9. **Recover saved work.** Edit and save a record, inspect its history and restore an earlier snapshot. Delete a test record and restore it from Trash with the same UUID. Inspect Saved changes and undo/redo a saved operation, including related-table effects. Reopen the app and verify history persists. Concurrent changes or incompatible schema must produce an explicit conflict. See [recovery](record-history.md).
10. **Keep files and links with records.** Add Attachment and URL fields. Select a generated local file, save, download it and compare its bytes. Open a valid URL using the explicit Open link action. Try files through a lookup and a gallery cover. Recover an attachment through record history. Uploading or saving a URL must not silently open it. See [attachments](attachments.md).
11. **Use automatic metadata.** Add automatic numbering, creation time and update time. Create records through two interfaces and verify distinct numbers. Save a change and check update time; attempts to overwrite service-owned values must fail. Deleting and restoring a record must follow the documented numbering/history semantics.
12. **Calculate and preview.** Add Quantity and Price and a currency Formula Total using `["Quantity"] * ["Price"]`. Preview real saved records before saving. Rename Quantity and reopen the formula; references must survive. Test `1 / 0` and a dependency cycle. Try date/array functions from the [formula guide](formulas.md) and clock-dependent values with Calculations. Results remain read-only, and errors must be explicit.
13. **Review complete groups.** Group by up to three scalar fields and choose numeric measures. Collapse/expand groups with mouse and keyboard; collapse choices should survive reopening locally. Copy/paste across groups, edit a grouping value and save. Headings and collapsed records must not receive edits. Counts and measures cover all matching records, not only loaded rows. Compare with Summarize and CSV. See [grouped records](grouped-records.md).
14. **Track status on a board.** Group a Board by a single-select Status. Open a card, create in an empty column and move cards using drag and the Move selector. Filter/search, then return to a grid. Colors and complete counts must remain consistent, including unloaded cards.
15. **Work with relative dates.** Try today, calendar weeks/months/years, past/next business days and elapsed hours with an explicit time zone. Check boundary records against exported results. Business days mean Monday–Friday, including public holidays; elapsed hours are timestamp intervals. Invalid settings and concurrent view edits must preserve the draft. See [relative dates](relative-date-filters.md).
16. **Schedule on a calendar.** Save a Calendar with start/end fields and a time zone. Navigate months, create on a day, open records and review unscheduled or invalid dates. Test a day requiring more than one page. Updates from another client should refresh counts and cards without losing an open draft. See [calendars](calendar-queries.md).
17. **Adjust a timeline.** Save a Gantt view and switch day/week scale. Move or resize a writable interval with pointer, keyboard and explicit controls. Confirm date-only spans and timestamp durations behave as documented, undo the change and test a stale edit. Missing/invalid dates remain accessible for correction. See [Gantt](gantt-views.md).
18. **Browse a gallery.** Save a Gallery with an attachment or lookup cover, card size and fit/crop setting. Browse multiple pages, search, open and edit a record, and verify changes from another client. Missing images and file errors must leave the record accessible. Reopen to verify settings. See [galleries](gallery-views.md).
19. **Connect an agent or application.** Follow the [MCP](mcp.md), [CLI](../apps/cli/README.md), [SDK](../packages/client/README.md), [Skills](agent-skills.md) or [Harness](harness.md) guide. Discover schema, create a field and record, query a saved view and make a version-checked update against the same service as the desktop. Verify the result from another interface.
20. **Recover a workspace.** Stop an isolated remote service while editing, restart it and inspect stored values before repeating any write with an uncertain outcome. Create an online backup, restore to a new path and connect to the restored workspace. Verify schema, links, history, files and views using the [backup guide](backup.md).

Repeat relevant steps in a narrow window and with enough fields/views to require scrolling. Controls, table context and keyboard focus should remain usable. Record the candidate checksum, OS, display refresh/scaling, input method and spreadsheet versions. For failures, include the step, expected/observed behavior and a minimal sample without private data. The report and walkthrough do not accept the product on the owner's behalf.

## Current boundaries

- Windows x64 portable desktop and one workspace per service. Bearer authentication grants full workspace access; enterprise administration, billing and real-time collaborative editing are outside scope.
- Explicit version-checked writes, preserved drafts and automatic refresh of saved changes; no offline replication or automatic retries of writes.
- Grids, boards, calendars, Gantt and galleries are implemented. Custom forms, pivot tables, dashboards, map views and automation remain **unimplemented and explicitly excluded from this goal**. A record-creation dialog is not a custom form; grouping is not a pivot table; MCP access is not an automation engine.
- Formulas use a bounded language. Acyclic lookup/formula dependencies are supported; recursive calculations, arbitrary JavaScript execution and an internal AI runtime are not.
- Record/page/field/attachment limits and supported query indexes are documented in the relevant guides. Measurements apply to their stated datasets and queries, not arbitrary workloads.
- Spreadsheet formats, type inference and input methods vary. Include your normal applications in final acceptance and follow the CSV/clipboard empty-value, date and formula-like-text semantics.
