# Grouped table records

In a grid view, choose **Groups**, select a field, and save. Use **Add grouping level** to nest up to three distinct fields in order; move or remove levels in Groups or View settings. Supported fields include text, multiline text, numbers, dates, timestamps, URLs, single-selects, checkboxes, automatic fields, scalar formulas and scalar linked summaries. Each heading shows its matching record count; records appear under the last level. Click a heading, or select it with the arrow keys and press Enter or Space, to expand or collapse it. **Collapse all** and **Expand all** work across the complete view.

Single-select groups follow the field's option order. Checkbox groups show unchecked, checked, then no value. Other values sort ascending: text is case-sensitive, numbers sort numerically, and dates use normalized values. **No value** and **Empty text** are distinct groups. Filters and search determine the matching records; sorting applies within each group. Hidden grouping fields still define their groups. Each view keeps its own grouping configuration.

Expand/collapse choices are remembered on this device when you close a table or restart the app. Each view and ordered combination of grouping field UUIDs/types has separate choices. Nested choices use the complete typed path, so identically named children under different parents remain independent. Collapsing a parent retains its children's choices. Renaming a field or option retains the choices; paths containing removed options are pruned. Filters and search can temporarily hide groups without discarding their choices. These are local presentation preferences, so folding a group does not change the shared query version or disrupt cell drafts. They are not included in a database backup and do not synchronize to other clients.

A failed group read retains the previous usable layout and does not save the failed choice. If local preference storage is unavailable, the app reports it while keeping the current layout usable; it does not retry the write automatically. Invalid stored choices reset visibly to expanded groups.

Edit cells and save as usual. A draft remains in its original group until it is saved, then the record moves to its new group. Saving clears the old selection with a notice; select records again before editing or opening details, because saved group positions may have changed. A failed write or a save without edits retains the selection. Collapsing a group retains its drafts and undo history. Copy and clear skip headings and collapsed records. Paste starts at a record cell and continues through expanded record rows, skipping headings and collapsed groups. A paste that exceeds those rows fails without partially changing drafts. Record details, duplication and deletion use record UUIDs rather than visual row numbers.

External changes load automatically while editing is idle. Group counts and visible records update together, retaining collapse choices and following a selected record by UUID when it remains in the prepared window. Active editors, composition, dialogs, drafts and undo/redo postpone replacement; a read failure keeps the current groups and records. Record, schema and view version checks prevent stale writes and inconsistent paging. A conflict retains your drafts for review; refresh or explicitly discard them before proceeding. CSV export includes all matching records, including collapsed groups, in the grouped view's order.

Choose **Groups → Add measure** to save up to 12 numeric sums, averages, minimums or maximums in a view. Each heading displays its count and configured measures, including when collapsed; hover it for the full text. Measures include every saved record matching the view's filters and search, regardless of visible pages. Unsaved cell drafts do not contribute until saved. Empty groups show a dash for each measure. Numeric formulas, automatic numbers and scalar linked summaries are supported. Remove a measure before deleting its field or converting it to an incompatible type. Renames retain the field UUID and update the displayed label. Removing grouping clears its saved measures.

Nested headings are indented; hover a heading to read its full ancestry and measures when its parent is offscreen. Parent counts and measures include all matching descendants. Root groups retain configured empty options, checkbox states and a null group; children contain actual matching values. Multi-selects, raw relation lists and array lookups are not scalar groups; a linked summary such as a sum or count can be grouped. Use **Summarize** for separate scalar summary/group operations. Native input-method and external spreadsheet round trips remain final-candidate acceptance checks.

## Shared interfaces

HTTP, SDK, CLI and MCP use the existing view operations:

```json
{
  "name": "By status and category",
  "type": "grid",
  "groupBy": ["<status-field-id>", "<category-field-id>"],
  "groupMeasures": [{ "fieldId": "<amount-field-id>", "operation": "sum" }],
  "query": {
    "sort": [{ "fieldId": "<amount-field-id>", "direction": "desc" }]
  }
}
```

Update with the current `expectedVersion` and `groupBy: null` to remove grouping. Grid queries return record pages in group order, without synthetic heading records. Use group-layout queries for complete counts and bounded heading windows. Pair their `expectedRevision`, `expectedViewVersion` and date context with the record query to keep counts and pages consistent. Board lane queries retain their existing behavior.

SQLite format 29 protects saved scalar grouping semantics; format 14 introduced select/checkbox groups. Migration preserves existing data and versions. The service indexes supported grouped sort orders independently of temporary searches and filters; linked summaries use their calculated query instead of an invalid SQLite subquery index. The client keeps up to 12 metadata windows, reads at most 500 segments per request and retains the visible window independently of cache eviction. Metadata reads are serialized; obsolete queued windows are skipped. An active read retains the queue until the service responds, because canceling HTTP does not cancel synchronous SQLite work. Its result is not applied to an abandoned viewport. It does not download every group or record before opening the view.

## Bounded scalar layout queries

`queryGroups(tableId, input, signal?)`, CLI `rowweave records groups TABLE_ID --input groups.json`, and MCP `records_groups` expose the same read-only [layout contract](http-api.md#group-layout-windows). For example, `{ "groupBy": "text-field-id", "offset": 10000, "limit": 50, "collapse": { "defaultCollapsed": true, "exceptions": ["Active"] } }` reads a deep display window while only the Active group is expanded. It does not download every preceding group.

The shared query interfaces and saved grids accept `groupBy: [firstFieldId, secondFieldId, thirdFieldId]` for up to three levels. A single field ID retains the scalar contract; a one-element array normalizes to that form. Nested segments identify typed ancestry through `path` and distinguish leaf record runs through `leaf`. Parent measures cover all matching descendants. Collapse exceptions are prefix paths such as `[["Active"], ["Active", false]]`; ancestor collapse hides child headings and records. Use the same ordered fields with `queryRecords`, or the saved view with `queryView`, to follow source offsets. [Nested layout semantics](http-api.md#group-layout-windows) define empty groups, visible heading counts and bounded expanded-record windows. SQLite format 31 gates saved nested arrays without rewriting records; view versions, schema dependencies, restart and backups include the full ordered hierarchy. Boards retain one single-select field.

The service calculates complete counts and prefix positions in one SQLite read snapshot. Only groups intersecting the requested display rows leave storage. Record offsets remain independent of collapse and match ordinary record queries with the same scalar `groupBy` or the saved grouped-grid query. Groups include configured empty select/checkbox headings and a null heading. Raw text is case-sensitive, numbers sort numerically, and dates/timestamps use stored normalized values. Group keys retain their types and never become display names.

For selected or pasted record ranges, use `window: "expandedRecords"`. Its offsets skip headings and collapsed records, so a small selection separated by thousands of collapsed groups needs only the intersecting group segments. Each segment includes `expandedOffset` alongside its display and record-query positions; clip to the requested interval before reading records. Both window kinds retain the same complete counts and revision guards. Desktop copy, clear, record actions and paste use these bounded reads and check operation limits before allocating record selections or changing drafts.

Shared-interface group queries accept numeric `measures`, such as `[{ "fieldId": "<amount-field-id>", "operation": "sum" }]`. Each returned group's `values` covers its complete matching records and follows the measure order. The same SQLite snapshot supplies counts, positions and measures; collapse and pagination do not change the totals. Up to 12 sum/average/min/max measures support numbers, numeric formulas, automatic numbers and scalar linked summaries. Nulls do not contribute; empty groups return null measures. A saved grouped view uses its `groupMeasures` when the read omits `measures`; an explicit array overrides that read only, including `[]` to omit values. Save `groupMeasures: []` through a versioned view update to remove its configured measures. SQLite format 30 protects these saved settings from older writers; migration preserves existing records and views.

Saved-measure regression tests cover more than 500 records in one group, read overrides, dependency validation, restart, backup/restore and format upgrades. SDK/CLI/MCP tests verify the same saved configuration and version conflicts. Automated desktop acceptance configures and reopens measures, verifies complete collapsed/empty group values, follows field renames and external record updates, retains saved totals while editing, recomputes after save, preserves record UUIDs and plain-text clipboard values, and reloads the renderer. These checks do not replace final native IME acceptance.

Tests cover more than 500 distinct groups, deep and past-end windows, cache eviction, large collapse exception sets, select order/renames, null and empty text, computed fields and linked summaries, filters, date rollover, stale schema/data/view guards, cancellation and HTTP/SDK/CLI/MCP parity. Automated desktop acceptance covers 800 text groups, deep keyboard editing, copying and pasting across 798 collapsed groups, a failed expanded-window read without partial edits, undo/redo and original record UUIDs. Existing select/checkbox, composition, fragmented viewport and automatic-refresh checks also apply. `node scripts/benchmark-group-layout.mjs` measures compiled service reads on an isolated 100,000-record dataset; renderer performance measurements remain separate.

For nested service workloads, run `node scripts/benchmark-nested-groups.mjs` after building. The [nested query report](nested-group-performance.md) separates the two-level workload and collapsed roots from unresolved high-cardinality three-level latency; these measurements do not establish renderer performance.
